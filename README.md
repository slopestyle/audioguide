# Аудиогид «Музей друзей»

Веб-аудиогид музея истории Красной Поляны и горнолыжного спорта.
Гость вводит номер стенда и слушает рассказ на своём языке — без установки приложений.

Дизайн и обоснование решений: [project-design.md](project-design.md).
Правила работы с кодом: [CLAUDE.md](CLAUDE.md).

## Запуск

```bash
npm ci
npm run dev      # http://localhost:5173/audioguide/
```

```bash
npm run typecheck   # проверка типов
npm test            # unit + DOM-тесты
npm run lint        # oxlint
npm run build       # сборка в dist/
```

## Публикация

Пуш в `main` запускает GitHub Actions, которые собирают проект и публикуют его
на GitHub Pages: https://slopestyle.github.io/audioguide/

Перед первой публикацией в настройках репозитория нужно включить
**Settings → Pages → Source: GitHub Actions**.

При переезде на собственный домен меняется одна строка — `base` в
[vite.config.ts](vite.config.ts) на `'/'`.

## Контент

Весь контент музея лежит в репозитории и не требует базы данных:

```
public/content.json      номера стендов, тексты и пути к файлам
public/media/<номер>/    ru.mp3, en.mp3, zh.mp3, ar.mp3, фото
```

Сейчас там **демонстрационные данные**: тексты-заглушки и звуковые тоны разной
частоты для каждого языка (чтобы на слух проверять переключение). Настоящий
контент зальётся через админку.

Формат аудио: mp3, 64–96 kbps, моно.

## Обработчик админки

Вход в админку по логину и паролю проверяет маленькая функция в Yandex Cloud
(`server/`). Она же хранит GitHub-токен и делает коммиты — в браузер токен
не попадает. Гостевая часть от неё не зависит.

### Развёртывание по шагам

**1. GitHub-токен для функции.** github.com → Settings → Developer settings →
Personal access tokens → **Fine-grained tokens** → Generate new token.
Repository access: **Only select repositories** → `slopestyle/audioguide`.
Permissions → Repository permissions → **Contents: Read and write** (больше
ничего не нужно). Срок — год. Токен показывается один раз, скопируйте сразу.

**2. Логины и пароли сотрудников.** По одной команде на человека:

```bash
npm run server:hash ivanov "Иван Иванов"
```

Команда печатает пароль (передайте его сотруднику) и готовую JSON-запись.
Записи всех сотрудников собираются в один массив — это значение `USERS`:

```json
[{"login":"ivanov","name":"Иван Иванов","salt":"…","hash":"…"}]
```

**3. Секрет для подписи сессий:**

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**4. Архив функции:**

```bash
npm run server:zip     # соберёт dist-server/ и упакует в function.zip
```

В архиве файлы лежат в корне, а не внутри папки `dist-server` — иначе точка
входа не найдётся.

**5. Аккаунт Yandex Cloud.** console.yandex.cloud → создать платёжный аккаунт
(нужна карта; в пределах бесплатного тарифа списаний не будет — наш объём это
сотни вызовов в месяц против бесплатного миллиона).

**6. Функция.** Cloud Functions → Создать функцию → имя `audioguide-admin` →
Создать версию:

| Параметр | Значение |
|---|---|
| Среда выполнения | `nodejs22` (подойдёт и 18/20) |
| Способ | Загрузить ZIP-архив → `function.zip` |
| Точка входа | `index.handler` |
| Таймаут | 30 секунд (публикация делает несколько запросов к GitHub) |
| Память | 256 МБ |

**7. Переменные окружения** (там же, при создании версии):

| Переменная | Значение |
|---|---|
| `SESSION_SECRET` | строка из шага 3 |
| `USERS` | JSON-массив из шага 2 |
| `GITHUB_TOKEN` | токен из шага 1 |
| `GITHUB_REPO` | `slopestyle/audioguide` |
| `GITHUB_BRANCH` | `main` |
| `ALLOWED_ORIGIN` | `https://slopestyle.github.io` |

**8. Публичный вызов.** На вкладке «Обзор» включить **Публичная функция** и
скопировать ссылку для вызова вида `https://functions.yandexcloud.net/<id>`.

**9. Проверка до захода в админку:**

```bash
npm run server:check -- https://functions.yandexcloud.net/<id> ivanov ПАРОЛЬ
```

Команда переводит ответ функции в причину: `500` — не заполнены переменные
окружения, `401` — не тот пароль, `403` — функция не публичная, `400` с
«invalid functionID» — в URL лишний хвост после идентификатора.

Адрес указывается **без пути**: подпути прямая ссылка на функцию не принимает,
поэтому действие едет полем `action` в теле запроса.

**10. Вход.** Открыть админку, раскрыть «Адрес обработчика», вставить ссылку
из шага 8, войти по логину и паролю.

Смена пароля или новый сотрудник — шаг 2, правка `USERS` и новая версия функции.
При переезде на свой домен поменять `ALLOWED_ORIGIN`.

Локальная разработка админки — без облака:

```bash
npm run server:dev   # http://localhost:8787
```

## Админка

Адрес: `https://slopestyle.github.io/audioguide/admin/`

Вход по логину и паролю. При первом открытии в поле «Адрес обработчика» нужно
один раз вписать URL функции — он сохранится в браузере.

Как устроена работа: на главном экране матрица готовности (стенды × языки),
клик по строке открывает карточку стенда с вкладками языков. Правки копятся
в черновике и переживают перезагрузку страницы; загруженные файлы живут только
до закрытия вкладки — при попытке уйти браузер предупредит. Кнопка
«Опубликовать» отправляет всё одним коммитом, изменения появляются в зале
примерно через минуту.
