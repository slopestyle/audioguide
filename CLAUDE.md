# Музей друзей — аудиогид

Веб-аудиогид музея истории Красной Поляны и горнолыжного спорта (3-й этаж нижней
станции канатных дорог «Альпика»/«Лаура»). Гость вводит номер стенда и слушает
рассказ на своём языке. ~30 стендов, языки: `ru`, `en`, `zh`, `ar`.

Полный дизайн и обоснование решений: @project-design.md

## Команды

```bash
npm run dev        # локальная разработка
npm run build      # сборка статики в dist/
npm run typecheck  # tsc --noEmit
npm run lint       # oxlint
npm test           # vitest: unit + DOM-сценарии (*.dom.test.tsx, happy-dom)
```

Playwright и axe пока не подключены — сценарии проходов покрыты DOM-тестами
`src/app/app.dom.test.tsx`. Доступность до появления axe проверяется вручную.

Перед коммитом: `npm run typecheck && npm run test && npm run lint`.

## Архитектурные инварианты

Их нельзя нарушать без явного решения владельца проекта — на них держится вся
экономика проекта (0 ₽ хостинга, нечему падать):

- **Нет бэкенда, нет БД, нет внешних API в рантайме.** Только статика на GitHub Pages.
- **Нет TTS и переводчиков в коде.** Озвучка и перевод делаются вне системы,
  админка принимает готовые mp3. Не добавлять интеграции с ElevenLabs/OpenAI/Yandex.
- **Контент — это данные, а не код**: `public/content.json` + `public/media/**`.
  Не редактировать их в задачах по коду; для тестов есть `fixtures/content.sample.json`.
- **Админ-бандл отделён от гостевого.** `src/app/**` не импортирует ничего из
  `src/admin/**`. Гость не должен скачивать код админки.
- **Один экземпляр `<audio>`** живёт в `src/core/player`. Экраны его не создают и
  не пересоздают — иначе звук обрывается при переходах.
- **Бюджет гостевого бандла — 100 КБ gzip.** Новая зависимость добавляется, только
  если она реально дешевле, чем написать это самому.
- **Язык может отсутствовать у стенда** — это штатное состояние, не ошибка.
  Любой код, читающий контент, обязан обрабатывать пропуск через фолбэк.

## Доступность — часть определения «готово»

Незрячие и слабовидящие посетители — профильная аудитория аудиогида, а не крайний случай.

- Размеры в `rem` (уважаем системный шрифт), цвета — только через CSS-переменные.
- Контраст ≥ 4.5:1, тач-цели ≥ 64 px, ничего не передаётся одним лишь цветом.
- Панель настроек: 3 размера текста, 4 цветовые схемы (ГОСТ Р 52872-2019),
  режим без изображений. Настройки сохраняются между экранами и сессиями.
- Семантический HTML, подписи ко всем интерактивным элементам, управляемый фокус.
- Для `ar` — `dir="rtl"` и зеркальная раскладка.
- Новый экран не считается готовым, пока его не проверили экранным диктором
  и в схеме «белым по чёрному» при размере текста A++.

## Стиль

- TypeScript strict, без `any`.
- Preact + обычный CSS с переменными. Без CSS-фреймворков и UI-китов.
- Комментарии объясняют «почему», а не «что». Код без комментариев — норма.
- YAGNI: не закладывать абстракции под гипотетическое будущее (вторая площадка,
  роли, оплата, геолокация). Появится задача — появится код.
- Тексты интерфейса не хардкодятся в компонентах, а лежат в словаре UI-строк.

## Безопасность

- **Репозиторий публичный** (условие бесплатного GitHub Pages). Ничего секретного
  в нём быть не должно: ни токенов, ни `.env`, ни персональных данных.
- Токен GitHub для админки существует только в браузере сотрудника (localStorage).
  Не добавлять его в код, конфиги, CI-переменные или примеры.
- Компрометация решается отзывом токена в GitHub — не изобретать свою авторизацию.

## Гит

- Ветки: `feat/*`, `fix/*`. Коммиты — в настоящем времени, по-русски или по-английски.
- Не смешивать в одном коммите изменения кода и заливку медиафайлов.
- Публикация контента идёт из админки автоматическим коммитом — не переписывать
  её историю и не делать force-push в `main`.
