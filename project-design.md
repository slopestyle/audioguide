# Аудиогид «Музей друзей» — дизайн проекта

**Дата:** 16 августа 2026
**Статус:** согласован, готов к реализации

---

## 1. Задача

Музей истории Красной Поляны и горнолыжного/сноубордического спорта занимает
третий этаж здания нижней станции канатных дорог «Альпика» и «Лаура». В зале
около 30 стендов со сквозной нумерацией.

Нужно дать посетителю возможность у любого стенда послушать рассказ об экспозиции
на своём языке, а сотруднику музея — самостоятельно управлять этим контентом.

**Языки:** русский (основной), английский, китайский, арабский.

**Ограничения:**

- Бюджет содержания — по максимуму бесплатно.
- Озвучка и перевод выполняются **вне системы**; админка принимает готовые mp3.
- У музея на старте нет ни сайта, ни домена, ни хостинга.
- В зале есть гостевой Wi-Fi.

**Критерии успеха:**

- Гость доходит от таблички до звука за считанные секунды, без установки приложений.
- Сотрудник обновляет контент сам, без разработчика.
- Система переживает сезон без обслуживания и без счетов.

## 2. Платформа

**Выбрано: статический сайт на GitHub Pages с браузерной админкой,
пишущей контент прямо в репозиторий через GitHub API.**

Объём данных: 30 стендов × 4 языка × 2–3 мин ≈ 120 файлов ≈ 200 МБ при 64 kbps моно.
Под такую нагрузку сервер не нужен.

### Рассмотренные альтернативы

| | A. Статика + GitHub Pages ✅ | B. Supabase free + статика | C. VPS в РФ + PocketBase |
|---|---|---|---|
| Цена | 0 ₽ | 0 ₽ до лимитов | ~200–300 ₽/мес |
| Админка | своя, пишет в репозиторий | своя, с логином | готовая из коробки |
| Риски | публикация ~1 мин, вход по токену | лимиты и заморозка при простое, зарубежная зависимость | оплата, обновления, бэкапы |

**Почему A:** контента мало и меняется он редко — это классическая задача для статики.
Отсутствие сервера и БД убирает большую часть того, что ломается: не нужно следить
за аптаймом, платить и бояться, что в разгар сезона музей останется без гида.
Git даёт бесплатную историю версий и откат в один клик.

Формат хранения нейтральный (`content.json` + папка медиа), поэтому переезд на
вариант C — копирование файлов, а не переписывание проекта.

**Принятые издержки:** репозиторий должен быть публичным (условие бесплатного Pages);
публикация занимает около минуты; для входа по логину и паролю нужен маленький
серверный обработчик — раздел 6.

## 3. Клиентский интерфейс

### Точка входа

Гость попадает на сайт по короткому домену (покупается, ~200 ₽/год) — адрес должен
влезать на табличку и запоминаться.

**Один плакат на входе в зал**: QR-код, крупный адрес, напоминание про наушники.
Гость сканирует один раз при входе; внутри зала — только ввод номеров.
На самих стендах QR не размещается (вне MVP), только крупная цифра.

### Три экрана

```
1. ВЫБОР ЯЗЫКА        2. ВВОД НОМЕРА          3. СТЕНД
┌──────────────┐      ┌──────────────┐       ┌──────────────┐
│  Музей       │      │  Музей   RU▾ │       │ ←  12   RU▾  │
│  друзей      │      │              │       │ ┌──────────┐ │
│              │      │      12      │       │ │  фото    │ │
│  Русский     │      │              │       │ └──────────┘ │
│  English     │      │  1   2   3   │       │ Первый бугель│
│  中文         │      │  4   5   6   │       │              │
│  العربية      │      │  7   8   9   │       │  ▶  ──○───   │
│              │      │  ⌫   0   ▶   │       │    1:12/3:40 │
│              │      │              │       │ ⏮ -15 +15 ⏭  │
│              │      │ Все стенды   │       │ ▾ Текст      │
└──────────────┘      └──────────────┘       └──────────────┘
```

### Решения и обоснования

- **Цифровая клавиатура на весь экран**, а не текстовое поле. Системная клавиатура
  мелкая, а гость на горнолыжном курорте часто в перчатках и с холодными руками.
  Кнопки от 64 px, переход по вводу 1–2 цифр.
- **Язык выбирается один раз** и запоминается. Переключение доступно прямо во время
  прослушивания **с сохранением позиции трека**.
- **Плеер минимальный**: play/pause, перемотка, ±15 сек, время. Без скоростей
  воспроизведения и плейлистов — в музее это шум.
- **Управление с экрана блокировки** (Media Session API): телефон в кармане,
  звук в наушниках, пауза с локскрина.
- **Текст-расшифровка скрыт под кнопкой** — нужен слабослышащим и тем, кто без
  наушников, но не должен перетягивать внимание.
- **Кнопки ⏮ ⏭ ведут на соседние номера** — при последовательном обходе не нужно
  возвращаться к клавиатуре.
- **Экран «Все стенды»** — список номеров с названиями.
- **Звук не прерывается при переходах**: приложение одностраничное, `<audio>` один
  на всё приложение.

**Вне MVP:** регистрация, избранное, карта зала, отзывы и оценки, маршруты,
автозапуск по геолокации, QR на стендах.

## 4. Доступность

Незрячий посетитель нуждается в аудиогиде больше зрячего, поэтому доступность —
часть базовой функциональности, а не отдельный «режим».

### Уровень 1 — работает всегда

- Полное управление с экранного диктора (VoiceOver/TalkBack): семантическая
  вёрстка, подписи ко всем элементам, управляемый порядок фокуса.
- **Аудио стартует автоматически** сразу после ввода номера — нажатие на цифру
  служит необходимым жестом пользователя. Незрячему не нужно искать кнопку play.
- Размеры в `rem`: системная настройка крупного шрифта уважается и ничего не ломает.
- Контраст от 4.5:1, тач-цели от 64 px, ничего не передаётся одним лишь цветом.

### Уровень 2 — панель настроек («Aa» в шапке)

| Настройка | Варианты | Зачем |
|---|---|---|
| Размер текста | A / A+ / A++ (100 / 130 / 170 %) | Самая востребованная опция у слабовидящих и пожилых |
| Цветовая схема | обычная / чёрным по белому / белым по чёрному / жёлтым по синему | Набор из ГОСТ Р 52872-2019; разные нарушения зрения требуют разных схем |
| Без изображений | вкл/выкл | Меньше визуального шума, легче для диктора |

Настройки сохраняются между стендами и сессиями.

Отдельная «версия для слабовидящих» как вторая копия сайта **не делается**: это
дублирование контента; одно приложение с переключателями решает ту же задачу и
удовлетворяет ГОСТ.

## 5. Модель данных и админка

### Хранение

```
content.json
media/
  12/
    photo.webp
    ru.mp3   en.mp3   zh.mp3   ar.mp3
```

```jsonc
{
  "updatedAt": "2026-08-16T10:00:00Z",
  "languages": ["ru", "en", "zh", "ar"],
  "stands": [
    {
      "number": 12,
      "photo": "media/12/photo.webp",
      "content": {
        "ru": { "title": "Первый бугель", "text": "…", "audio": "media/12/ru.mp3", "duration": 220 },
        "en": { "title": "The First Rope Tow", "text": "…", "audio": "media/12/en.mp3", "duration": 235 }
        // zh, ar могут отсутствовать, пока не залиты
      }
    }
  ]
}
```

**Ключевой контракт: язык может быть не заполнен — это штатное состояние.**
Музей стартует с русским и английским, остальные доезжают позже.

### Админка (`/admin`)

1. **Вход** — логин и пароль сотрудника; проверяет их серверный обработчик
   (раздел 6). GitHub-токен в браузер не попадает вообще.
2. **Матрица готовности** — 30 строк × 4 языка, сразу видно, где нет аудио или
   текста. Главный рабочий экран.
3. **Карточка стенда** — номер, фото и вкладка на каждый язык: название, текст,
   mp3 с перетаскиванием и немедленным прослушиванием для самопроверки.
4. **Фото сжимается в браузере** до ~1600 px — сотрудник не думает про размеры.
5. **«Опубликовать»** — все правки уходят одним атомарным коммитом; через ~1 минуту
   они в зале. Статус показывается явно.
6. **Откат** к предыдущей публикации — это git-история.

### Ограничения

- Репозиторий публичный: ничего внутреннего в нём быть не должно.
- Аудио принимается в mp3 64–96 kbps моно, **до 2.5 МБ на файл**: таков предел
  одного запроса к бесплатной функции. При 64 kbps это около 5 минут звука —
  вдвое больше типичного рассказа. Перекодирования в браузере нет.
- Пароли и GitHub-токен хранятся на стороне обработчика, в репозитории их нет.

## 6. Авторизация и публикация

Гостевая часть остаётся чистой статикой. Но логин и пароль требуют того, кто их
проверит, поэтому появляется один маленький серверный обработчик — бесплатная
функция в Yandex Cloud.

**Почему Yandex Cloud:** серверы в России, то есть нет риска блокировок и
замедлений при работе из Сочи; наш объём — сотни запросов в месяц против
бесплатного миллиона. Запасной вариант — Cloudflare Workers.

```
сотрудник → /admin (статика на Pages) → логин + пароль
                        ↓
             функция (Yandex Cloud, 0 ₽)
             • проверяет пароль по хешу
             • выдаёт сессию на 12 часов
             • хранит GitHub-токен у себя
                        ↓
             коммит в репозиторий → Actions → Pages → зал
```

Если функция недоступна, гостевая часть продолжает работать — недоступна только
публикация нового контента.

### API обработчика

Все вызовы идут POST-запросом на один адрес, а действие передаётся полем
`action` в теле: прямая ссылка на функцию в Yandex Cloud не принимает подпути —
`/<id>/login` она считает испорченным идентификатором. Маршрут в пути тоже
понимается, если однажды появится API Gateway.

| Действие | Назначение |
|---|---|
| `login` | логин и пароль → токен сессии, имя сотрудника, срок годности |
| `state` | текущий коммит репозитория — чтобы поймать чужую публикацию |
| `blob` | один файл (≤ 2.5 МБ) → его хеш в git |
| `commit` | список изменений + базовый коммит → одна публикация |

Файлы грузятся по одному, а коммит делается отдельным вызовом, потому что предел
одного запроса к функции — 3.5 МБ. Атомарность при этом не страдает: до вызова
`/commit` загруженные объекты в репозитории ни на что не влияют, дерево файлов
меняется одним действием.

### Требования к авторизации

Это не общие слова, а проверяемый список:

- пароль хранится только как хеш PBKDF2-SHA256 (600 000 итераций) с личной солью;
- сравнение хешей — за постоянное время, чтобы по времени ответа нельзя было
  подбирать пароль;
- сессия — токен, подписанный HMAC-SHA256, с явным сроком годности; в браузере
  живёт в `sessionStorage` и исчезает при закрытии вкладки;
- обработчик кросс-доменный, поэтому сессия передаётся заголовком `Authorization`,
  а не cookie: при таком способе CSRF-атака невозможна в принципе;
- пароли и GitHub-токен — переменные окружения функции; в репозитории их нет;
- смена пароля или добавление сотрудника — правка переменной и передеплой.

Блокировка после N неудачных попыток требует внешнего хранилища состояния —
для функции это лишняя зависимость и лишняя точка отказа. Вместо неё от перебора
защищают медленный хеш (~300 мс на попытку) и длинный пароль, который сотрудник
получает готовым, а не придумывает сам.

## 7. Технологии и архитектура

| Слой | Выбор | Обоснование |
|---|---|---|
| Сборка | Vite + TypeScript | Стандарт, на выходе статика |
| UI | Preact (~4 КБ) | Нужны компоненты, но React на 45 КБ для трёх экранов избыточен |
| Стили | Обычный CSS + переменные | Цветовые схемы доступности переключаются сменой набора переменных |
| Роутинг | свой, ~20 строк | Библиотека тяжелее задачи |
| Данные | `content.json` + `media/` | БД нет |
| Деплой | GitHub Actions → Pages | Коммит → через ~1 мин в зале |

Бюджет гостевого бандла — **100 КБ gzip** (ожидаемо 60–80 КБ), дальше грузится
только аудио.

```
src/
  app/     экраны гостя: язык, ввод номера, стенд, список
  admin/   админка (отдельная точка входа, в основной бандл не попадает)
  core/    модель контента, выбор языка, плеер, настройки доступности
  ui/      кнопки, клавиатура, панель настроек
public/
  content.json
  media/…
```

Админка собирается **отдельным бандлом**: гость не должен платить трафиком за код,
которым не пользуется.

### Поток данных: гость

```
домен → HTML+JS (~70 КБ) → content.json (≈50 КБ gzip, весь контент на 4 языках)
   ↓
выбор языка (запоминается) → клавиатура → номер 12
   ↓
экран стенда → <audio src="media/12/ru.mp3"> → автозапуск
   ↓
трек стримится с CDN и кэшируется браузером
```

Каталог приходит одним файлом при первом заходе, поэтому переходы между стендами
мгновенные — сеть после старта нужна только под аудио. Service worker кэширует
оболочку и `content.json`: при мигающем Wi-Fi приложение продолжает работать.

### Поток данных: админка

```
/admin → токен из браузера → чтение content.json и media/ через GitHub API
   ↓
правки копятся локально (черновик переживает закрытие вкладки)
   ↓
«Опубликовать» → все файлы одним коммитом (Git Data API)
   ↓
Actions пересобирают → ~1 мин → изменения в зале
```

Коммит атомарный: обрыв связи не может оставить стенд с китайским текстом и русским
звуком. Перед отправкой сверяется базовый коммит — при чужой публикации выводится
предупреждение вместо тихой перезаписи.

## 8. Обработка ошибок

Гость не видит технических формулировок: каждое сообщение отвечает, что произошло
и что делать.

| Ситуация | Что видит гость |
|---|---|
| Номера не существует | «Стенда № 47 нет. Проверьте номер на табличке» + «Все стенды» |
| Стенд не озвучен на его языке | «Этот стенд ещё не озвучен на арабском. Доступно: Русский, English» с кнопками переключения; текст на его языке показывается, если есть |
| Аудио не загружается | «Не удаётся загрузить аудио. Проверьте подключение к Wi-Fi музея» + «Повторить»; уже загруженное продолжает играть |
| Автозапуск заблокирован браузером | Крупная кнопка ▶ вместо сообщения об ошибке |
| Не загрузился `content.json` | «Не удалось загрузить гид» + «Повторить»; service worker отдаёт последнюю сохранённую версию |

**В админке — наоборот, прямо и подробно:**

- Неверный логин или пароль → одно общее сообщение на оба случая: подсказывать,
  что именно неверно, — значит помогать подбирать.
- Сессия истекла (12 часов) → просьба войти заново; черновик при этом не теряется.
- Кто-то опубликовал раньше → «Контент изменился. Обновить и наложить правки?».
- Файл больше 2.5 МБ или не mp3 → отказ с объяснением формата до отправки.
- Обрыв связи при публикации → повтор; частичной публикации не бывает.

## 9. Тестирование

Тестируем по стоимости ошибки, а не сплошным покрытием.

1. **Unit (Vitest)** — логика с тихими отказами: выбор языка с фолбэком, валидация
   номера, разбор `content.json`, форматирование времени.
2. **E2E (Playwright)** — пять сценариев, обязательных ко дню открытия: ввод номера →
   играет звук; смена языка сохраняет позицию; незаполненный язык → корректное
   сообщение; переходы вперёд/назад; настройки доступности переживают перезагрузку.
3. **Доступность** — axe в CI без нарушений плюс ручная проверка с VoiceOver и
   TalkBack: автотесты не ловят «диктор читает кнопку как *кнопка*».
4. **Админка** — тесты на моке GitHub API: черновик, конфликт версий, отозванный токен.
5. **Ручной чек-лист перед запуском** — iPhone Safari, Android Chrome, экран
   блокировки с наушниками, арабский RTL и обязательно прогон в самом зале на
   музейном Wi-Fi.

Не делаем: нагрузочное тестирование (30 посетителей — не нагрузка для CDN) и
визуальные регрессии.

## 10. Визуальный язык

Основано на фирменном плакате музея: гравюрная эстетика, тёмно-зелёный и глубокий
красный на кремовом.

### Палитра

| Токен | Значение | Роль | Контраст на фоне |
|---|---|---|---|
| `--bg` | `#F1E9DD` | фон | — |
| `--ink` | `#1C3B2E` | текст, шапка, основные кнопки | 10.4:1 |
| `--accent` | `#8E1C24` | play, активный язык, акценты | 7.4:1 |
| `--line` | `#1C3B2E` @ 20 % | рамки, разделители | — |

Тёмная тема переворачивает роли (`#12241C` фон, кремовый текст); красный при этом
светлеет до `#D96B72` — исходный на тёмном фоне нечитаем. Схемы доступности
полностью замещают фирменные цвета — это ожидаемое поведение.

### Шрифты

Все бесплатные (OFL) и самохостятся в репозитории — без Google CDN: быстрее на
слабом Wi-Fi и без внешних зависимостей. Сабсет латиница + кириллица ≈ 30–40 КБ
на начертание.

- **Заголовки и цифры — Oswald.** Бесплатный родственник плакатного узкого гротеска
  с фирменного макета, полная кириллица. Цифры на экранной клавиатуре набираются
  им же, что и номера на табличках: гость видит на экране ту же цифру, что на стенде.
- **Текст интерфейса и расшифровки — Inter.** Крупный рост строчных, читается при
  увеличении до 170 % и в режиме высокого контраста. Альтернатива с более русским
  характером — Golos Text.
- **Китайский — системные шрифты** (PingFang SC / Noto Sans SC / Microsoft YaHei).
  CJK-вебшрифт весит 2–10 МБ и уничтожил бы бюджет загрузки ради одного языка.
- **Арабский — Noto Sans Arabic**, сабсет ~60 КБ, кегль увеличен примерно на 10 %:
  вязь при равном размере читается мельче латиницы.

Стилизованная визуальная оболочка (компоненты, иллюстрации, детали оформления)
разрабатывается отдельно на основе дизайн-системы и накладывается на готовый код.
